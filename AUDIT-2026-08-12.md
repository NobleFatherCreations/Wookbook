# Full live audit — 2026-08-12

Method: every page fetched live with `curl`, then rendered in headless Chromium
(local server against the fetched bytes, since this sandbox can't reach outbound
domains from the browser). Checked per page: HTTP status, body background, text
length, visible element count, `pageerror`, horizontal overflow, which
cross-project nav is present, and cross-link/naming consistency. **Nothing below
is inferred from reading source — it is all measured against what is live.**

## Root cause of most of it

The cross-project nav ("THE HOUSE" / the catalogue) is **hand-pasted into every
page** instead of generated from `sites.json`. CLAUDE.md already forbids this
("Generate from it, never hand-maintain per page … THE HOUSE cross-project map"),
but the rule was never applied to this component. Result: **three** different
states shipped simultaneously, and neither generation learned about the two
newest projects.

| nav generation | pages |
|---|---|
| `nf-seal` coin + right drawer (current) | root, feminine, children, wook, fractal, fracture, shadowroot, portals, press |
| `nh-*` red "THE HOUSE" side tab (older) | loop, scale, playbook, music |
| **none at all** | faith, festival (Festie Bible), resin (Casting) |

Festie Bible and Casting appeared in **0 of 14** book catalogues (hub only).

## Not reproducible — need detail

- **Portals day/night**: measured working. Hero pieces have `dayNatural=700`,
  `opacity:1`, `clip-path: inset(0 38% 0 0)`, `--wipe:62%`; screenshot shows day
  on the left, glow on the right, knob draggable. There *is* a latent trap:
  `body.night .reveal .day{opacity:0}` hides every day image and the night
  toggle slides all wipes to `0%`, so if "Cut the lights" or "LIGHTS OUT" is on,
  everything is glow-only until toggled back. Suspect that, or the 10.4MB page
  weight delaying decode on LTE.
- **Festie Bible "white background"**: its body is `#141019` and there are no
  large light surfaces on it. The pages that *are* light are **faith**
  (`#f5f0e6`) and **scale** (`#f7f2e8`), and **children** has a fully
  transparent body (renders white behind).

## Other findings not reported

- `faith` — no nav at all, still links to two raw `netlify.app` addresses, and
  only ~1.8k chars (intro gate; the 27-tradition content gap is task #56).
- `children` — `body` background is `rgba(0,0,0,0)`; needs an explicit colour.
- `playbook` + `music` have **no local source** in the repo, so the only copy is
  whatever is deployed. That is exactly how the music data was lost.
- File naming is inverted vs. slugs: `noble-father-festival.html` is the Festie
  **Codex** (`/wook`), `noble-father-festiebible.html` is the Festie **Bible**
  (`/festival`).
- `sites.json` calls `/faith` "The Coercive Control Codex"; the page and hub both
  say "The Sacred Divide".

## Prevention (task #81)

1. Generate the nav block from `sites.json` into every page; never hand-edit it.
2. Commit `playbook` and `music` sources into the repo — no live-only files.
3. `scripts/verify-live.mjs`, run before calling any round done, asserting per
   page: 200, zero `pageerror`, nav present, every referenced asset 200, one
   canonical name per project, no horizontal overflow, nothing stuck at
   `opacity:0` under reduced motion. **A declared-but-undefined data const
   (`TRACKS`, `SCENARIO_INDEX`) is a `pageerror` — this check would have caught
   both.**
